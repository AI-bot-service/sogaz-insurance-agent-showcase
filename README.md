# СОГАЗ ИИ-агент по страхованию имущества — витрина для проверки задания

Этот репозиторий — **публичный извлечённый фрагмент** коммерческого проекта,
выполненного по заказу. Полный проект закрытый (NDA, приватный репозиторий,
доступ к боевой инфраструктуре и данным клиентов заказчика), поэтому здесь
собрана та часть, которую можно показать без риска: описание задачи,
архитектура и код без секретов, персональных данных и внутренних деталей
инфраструктуры заказчика.

**Кому это адресовано:** куратору/проверяющему домашнее задание —
чтобы оценить объём и качество проделанной работы без доступа к приватному
репозиторию.

## Что это за проект

ИИ-помощник страхового агента для продукта СОГАЗ «Персональное решение+»
(страхование квартиры и дома):

1. Клиент пишет боту в Telegram или MAX.
2. Бот определяет тип объекта и ведёт диалог по чек-листу нужных для расчёта
   полей — можно текстом, голосом или фото.
3. Данные оцифровываются и приводятся к нужному типу (даты, телефон, адрес
   через DaData), сомнительные значения бот переспрашивает.
4. Параллельно бот консультирует клиента по продукту — поиск по базе знаний
   СОГАЗ (RAG) с ответом через GPT-4o-mini.
5. Когда все обязательные поля собраны — клиенту показывается сводка на
   подтверждение.
6. После подтверждения заявка уходит на расчёт и создание проекта полиса —
   через RPA (автозаполнение личного кабинета СК) или агентское API.

Подробнее — [ARCHITECTURE.md](ARCHITECTURE.md).

## Моя роль

Спроектировал и реализовал бэкенд целиком: диалоговый движок на tool-calling
поверх OpenAI, RAG-консультацию, схему данных и декларативные чек-листы,
голосовой и фотоввод, нормализацию адресов, абстракцию над разными способами
передачи заявки в страховую компанию (RPA / API / оператор), безопасность API
(токены по времени-постоянному сравнению, минимальная длина, отпечатки в
логах вместо самих токенов).

## Технологии

Python 3.12, FastAPI, SQLAlchemy 2.0 (async) + PostgreSQL/pgvector, Redis,
aiogram3 (Telegram), собственный клиент к Bot API мессенджера MAX (httpx),
OpenAI (gpt-4o-mini — диалог и vision, whisper-1 — распознавание речи,
text-embedding-3-small — эмбеддинги), Playwright (RPA), DaData (нормализация
адресов), Docker/Docker Compose, Traefik.

## Что показано в этом репозитории

```
src/
  main.py               — сборка FastAPI-приложения
  core/                 — конфигурация, подключение к БД, проверка токенов доступа
  bot/                  — диалоговый движок, каналы Telegram и MAX, общий рантайм
  checklists/           — декларативные YAML-чек-листы полей заявки + загрузчик
  calc/                 — абстракция способа расчёта (RPA / агентское API / оператор),
                           выбор продукта по бизнес-правилу заказчика
  digitize/             — приведение значений к типу поля, распознавание речи
  rag/                  — эмбеддинги, индексация базы знаний, поиск
  services/             — консультации, верификация данных, LLM-обвязка, история диалога
  models/, schemas/     — модели данных заявки и диалога
```

Код взят из рабочего репозитория «как есть» (за вычетом раздела ниже) —
не адаптирован специально под демонстрацию.

## Что сознательно не публикуется — и почему

Технический курс проекта отдельно отмечает эти материалы как закрытые
(`.claude/settings.json` в приватном репозитории явно запрещает их читать
даже мне самому в рабочих сессиях):

- **Карта полей формы AdInsure** (`docs/adinsure_fields/`) и HAR-дампы, из
  которых она снята — это структура внутренней формы личного кабинета
  заказчика, полученная в рамках работы с его закрытой системой.
- **Записи прохода по форме и снимки боевого ЛК** (`records/`, `dumps/`) —
  содержат персональные данные клиентов заказчика.
- **Бизнес-документы заказчика** (Правила страхования, КИД, Памятка, формы
  заявлений в PDF/DOCX) — переданы заказчиком для внутреннего использования.
- **Секреты**: `.env`, токены API (OpenAI, DaData, СОГАЗ), токен доступа к
  агентской машине (`agent/config.toml`).
- **API-роутеры админки** (`app/api/v1/agent*.py`, `applications.py`,
  `checklists.py`) — работают с персональными данными клиентов и очередью
  внешнего Windows-агента.

Код в `calc/rpa_runner.py` в этом репозитории — реальный файл из рабочего
репозитория: карта CSS-селекторов формы (`FLAT_FIELD_MAP`/`HOUSE_FIELD_MAP`)
в нём остаётся пустым каркасом с `TODO` — фактические селекторы вынесены и
собираются отдельно из `docs/adinsure_fields/` (см. пункт выше), поэтому файл
можно показывать как есть.
